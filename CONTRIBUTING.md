# Contributing

Thank you for taking the time to examine this project closely enough to consider changing it.

Human Stability Infrastructure is still early, which means disagreement is not a threat to the project. It is part of the work.

The most useful contributions will usually do one of four things: identify something that does not work, clarify something that is difficult to understand, connect the framework to evidence or practice it has overlooked, or show how an idea behaves differently in the real world than it does on paper.

## What good contributions look like

You do not need to agree with the framework to contribute.

If you believe an idea duplicates existing practice, say so and provide the closest comparison you know.

If a role would create unnecessary work for practitioners, explain where the burden appears.

If language would feel dehumanizing to a participant, point to the language and explain why.

If a safeguard would fail under real organizational pressure, describe the failure condition.

If the entire framework becomes unnecessary once an existing method is considered, that is important information too.

## Evidence

Please distinguish between what you observed, what you believe, what existing evidence supports, and what still needs investigation.

A strong contribution can absolutely begin with professional judgment or lived experience. It becomes more useful when the reader can understand which parts come from direct experience and which parts are broader claims.

## Privacy

Do not submit identifying participant information.

That includes names, addresses, dates of birth, case numbers, medical record numbers, phone numbers, email addresses, photographs, detailed legal identifiers, or combinations of facts that could reasonably identify a person.

Use synthetic or appropriately de-identified examples.

If useful feedback cannot be provided without exposing someone's identity, do not post it publicly. Email phoenx2025@gmail.com with only the type of concern, as described in the Code of Conduct.

## Scope

This repository is intended for exploratory research, coordination thinking, implementation review, and framework development.

Contributions should not convert the project into a predictive, punitive, diagnostic, clinical, sentencing, eligibility, surveillance, or automated decision system.

See `safeguards/safeguard-baseline.md` before proposing changes to a role or workflow.

## Making a contribution

For a small correction, a pull request is appropriate.

For a conceptual disagreement, implementation problem, or larger proposed change, start with an issue using the forms in `.github/ISSUE_TEMPLATE/`.

Please explain the problem before presenting the solution. That helps other contributors evaluate whether the proposed change actually addresses the same problem.

Do not submit material you do not have the right to share.

## AI-assisted contributions

AI tools may be used to help draft, organize, compare, or review contributions, but contributors remain responsible for what they submit.

Do not present generated citations, legal interpretations, clinical claims, research findings, or implementation evidence as verified unless you have actually checked the underlying source.

The repository should become more reliable as it grows, not more confident.

## Credit

Meaningful contributions should receive appropriate acknowledgment.

Submitting a contribution does not transfer ownership of a contributor's unrelated work, research, organization, or identity to this project.

## The question worth keeping nearby

When considering a change, ask whether it helps people understand instability more clearly and respond more responsibly without giving the system more authority over the person than it needs.
